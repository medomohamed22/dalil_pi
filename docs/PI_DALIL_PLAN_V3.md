## ٣. خطة الواجهة وتجربة الاستخدام (UI/UX)

### أولوية 1 (قبل التقديم)
1. **أزرار متابعة بعد النتايج:** "أرخص" و"تقييم أعلى" و"قريب مني" و"قارن أول اتنين". بتبعت سؤال متابعة بضغطة، زي Rufus.
2. **شاشة تفاصيل المنتج:** لما تدوس على الكارت تفتح شاشة من تحت فيها الصور كلها، والتقييمات الحقيقية، وتفاصيل رقم الثقة، والشحن، وزرار الطلب. الكارت نفسه يبقى أبسط.
3. **مقارنة:** تختار 2 أو 3 منتجات وتشوفهم جنب بعض (السعر، الثقة، التقييم، الشحن، المسافة).
4. **جولة تعريفية في 3 خطوات** أول مرة بعد الدخول: ابحث، شوف الثقة، اطلب من المتجر.
5. **حالات الخطأ والانتظار:** زرار "جرّب تاني"، وشريط لما النت يقطع، ورسالة واضحة لما البحث يطوّل ("بندوّر في 3 متاجر…").

### أولوية 2 (بعد التقديم)
- **المفضلة وتنبيه السعر:** تتابع منتج، والمهمة اليومية تبعتلك لو سعره نزل.
- **سجل البحث** كأزرار سريعة في الشاشة الفاضية.
- **إمكانية الوصول:** تباين ألوان AA، وقراءة الرد للشاشة أول بأول (aria-live)، وأزرار مساحتها 44px على الأقل.
- **الأرقام:** اختيار بين ٠١٢ و012 في العربي.

### الأنيميشن
- **القاعدة:** نحرّك الشفافية والمكان بس (opacity وtransform) علشان مايبطّأش الموبايل. المدة من 150 لـ 250 ملي ثانية، وsprings للشاشات اللي بتطلع من تحت. ✅ وبنحترم "تقليل الحركة".
- **الكروت:** بتظهر واحد ورا التاني بفرق 40 ملي ثانية (ده موجود).
- **رقم الثقة:** يعدّ من 0 لحد الرقم (حوالي 600 ملي ثانية) أول ما يظهر.
- **الدفع:** علامة ✓ متحركة بعد ما الباقة تتفعّل أو الطلب يتعمل.
- **من الكارت لشاشة التفاصيل:** الكارت يكبر ويبقى هو الشاشة (shared element). ده محتاج ميزة "layout" تتحمّل لشاشة التفاصيل بس، علشان الصفحة الأولى تفضل خفيفة.
- **اللوجو وهو بيفكّر:** موجود ✅.

## ٤. نستفيد أقصى استفادة من Vercel المجاني (Hobby)

**المسموح كل شهر:**

| المورد | الحد |
|---|---|
| تشغيل الدوال (Function Invocations) | مليون |
| وقت المعالج الفعلي (Active CPU) | **4 ساعات** ← ده أضيق حد عندنا |
| الذاكرة (Provisioned Memory) | 360 GB-hrs |
| نقل البيانات | 100 GB |
| طلبات الـ CDN | مليون |
| تحسين الصور | 5,000 |
| Web Analytics | 50 ألف حدث |
| Speed Insights | 10 آلاف حدث |
| أقصى مدة للدالة | 300 ثانية |

لو حد اتعدّى، الميزة بتقف لحد ما 30 يوم يعدّوا.

> ⚠️ **مهم:** باقة Hobby **للاستخدام الشخصي غير التجاري بس**. أول ما الاشتراكات المدفوعة تشتغل على الشبكة الرئيسية بفلوس حقيقية، لازم ننقل لـ **Pro** (20 دولار في الشهر)، ونحسبها في المصاريف الثابتة.

**إيه اللي بياكل الحد:** متصفح Chromium اللي بيبحث في سلة بياخد تقريباً من 3 لـ 8 ثواني معالج في كل بحث. يعني 4 ساعات تكفي تقريباً من 2,000 لـ 4,000 بحث بالمتصفح في الشهر.

**اللي اتعمل ✅:**
- السيرفر في لندن.
- ذاكرة مؤقتة للبحث (10 دقايق).
- منع فتح تطبيقات باي في المتصفح.
- مهمة يومية (Cron).
- كود الصفحة أخف.
- كاش لملفات الصوت والأيقونات.

**الخطوات الجاية ⏳:**
1. **الـ API بتاع سلة وMap of Pi:** بيشيل المتصفح من أغلب عمليات البحث. ده أكبر توفير في وقت المعالج.
2. **تفعيل Speed Insights وWeb Analytics** من لوحة Vercel (مجانيين في الحدود اللي فوق)، علشان نقيس السرعة على موبايلات المستخدمين الحقيقية.
3. **صور المنتجات:** مش هنستخدم تحسين الصور بتاع Vercel ليها (الحد 5,000 صورة بس)، وهنكمّل بالتحميل الكسول (lazy).
4. **سعر الباي:** نفصله في رابط بيتخزّن على الـ CDN لمدة 60 ثانية، علشان نقلل تشغيل الدوال.
5. **المتابعة:** نبص على تبويب Usage في Vercel كل أسبوع، وأهم رقم هو Active CPU.

## ٥. قاعدة البيانات (Supabase المجاني)

**المسموح:**
- 500 MB للداتا.
- 5 GB نقل بيانات (egress).
- طلبات API من غير حد.
- مشروعين نشطين بالكتير.
- **المشروع بينام بعد أسبوع من غير استخدام.**

**اللي اتعمل ✅:**
- قاعدة البيانات والسيرفر في نفس المدينة.
- 6 فهارس.
- البحث بقى بطلبين بدل 9، وفتح الموقع بطلب واحد بدل 3.
- "آخر ظهور" بيتكتب مرة في الساعة.
- العدادات القديمة بتتمسح كل يوم، والمهمة اليومية بتمنع النوم.
- صفحة الطلبات بتجيب الأعمدة المطلوبة بس.

**الخطوات الجاية ⏳:**
1. **ملخص العرض جوه الطلب (offer):** نشيل منه التفاصيل اللي مش محتاجينها، زي أجزاء الثقة والتعليقات، علشان نقلل الحجم.
2. **صفحات للطلبات** (20 طلب في المرة) بدل 50.
3. **حدود الطلبات لكل IP:** تتحسب في ذاكرة السيرفر الأول، وقاعدة البيانات للحدود المهمة بس (اليومي والساعة).
4. **مراجعة شهرية** لتنبيهات الأداء والأمان في Supabase، ولأبطأ الاستعلامات (pg_stat_statements).
5. **نسخة احتياطية:** الباقة المجانية مفيهاش نسخ احتياطي لحظي (PITR)، فنعمل تصدير أسبوعي للجداول المهمة (الاشتراكات والمدفوعات والطلبات).

## ٧. الشراكات

**اللي هنعرضه على أي شريك:**
- زوار ومشترين بالباي ببلاش.
- علامة **"موثّق في دليل باي"** على المتجر.
- طلبات بالعنوان كامل (طلب أوتوماتيك).
- مستقبلاً: عمولة إحالة على المبيعات.

**الشكل التقني:** أي شريك يقدر يربط بـ "Dalil Pi Partner API v1" (`docs/PARTNER_APIS.md`)، أو يبعتلنا الـ API بتاعه وإحنا نعمل ربط صغير.

| الشريك | نطلب منه إيه | إزاي نوصله | الحالة |
|---|---|---|---|
| **سلة شوب** (ومعاها Salla Care وSalla Go والخدمات) | API للبحث، وبعدين للطلبات، وعمولة إحالة | `support@salla-shop.com` | الرسالة جاهزة |
| **Map of Pi** | إذن الـ API، والرابط، والمفتاح | فورم Let's Connect على mapofpi.com، أو X ‎@mapofpi، أو تليجرام، أو GitHub | الرسالة جاهزة |
| **فريق Pi Core Team** | إدراج في Pi App Studio أو دليل التطبيقات، والانتقال للشبكة الرئيسية، ودعم الهاكاثون | بوابة المطورين (develop.pi) وقنوات الهاكاثون | بعد التقديم |
| **متاجر ووردبريس اللي عليها سلة نت باي** | تسجّل في دليل باي علشان الطلب الأوتوماتيك يشتغل عندها | صفحة "دليل باي للتجار" ⏳ | الربط جاهز ✅ |
| **بيكت بليس وباي تشين مول** | فيد منتجات أو API | من تطبيقاتهم في متصفح باي | ⏳ |
| **محلات محلية في مصر** | تسجّل محلها مباشرة (اسم، مكان، منتجات، محفظة) | فورم "ضيف محلك" في دليل باي ⏳ | ⏳ |

**ميزة جديدة مقترحة:** صفحة **"دليل باي للتجار"**. التاجر يسجّل بحساب باي، ويثبت إنه صاحب المحفظة، ويضيف منتجاته أو رابط متجره. ده يخلّينا مش معتمدين على API الشركات الكبيرة بس.

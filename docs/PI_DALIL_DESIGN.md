# Pi Dalil (دليل باي) — تصميم الفكرة

> وكيل تسوّق بالذكاء الاصطناعي، يبحث **فقط** في المتاجر اللي بتقبل Pi بشكل مؤكد، ويحسب لكل متجر **رقم ثقة** بمعادلة واضحة، ويجيب تقييمات المتجر والمنتج، والمستخدم **يدوس "ادفع بـ Pi"** والطلب يتسجل في المتجر تلقائياً ببياناته.
>
> مبني على نفس DNA مشروع **Dalil** (هاكاثون PayPal): أسعار موقّعة، ترتيب محايد بدون إعلانات، الفلوس **تتحجز الأول ومتتحولش** إلا لما الطلب يتأكد، والسيرفر هو اللي بيفرض القواعد مش الـ AI.

---

## 1. المشكلة
1. **الرواد معاهم Pi ومش لاقيين يصرفوه فين.** المتاجر موجودة (Map of Pi، تطبيقات Mainnet على `pinet.com`، مواقع بتعلن إنها بتقبل Pi) لكن متفرقة ومفيش مكان واحد تدور فيه.
2. **النصب كتير.** مواقع بتقول "بنقبل Pi" وهي بتسرق الـ passphrase أو بتاخد الفلوس وتختفي. الرائد مش عارف يثق في مين.
3. **الشراء متعب.** كل متجر له طريقة: تملا بياناتك، تحوّل يدوي، تبعت سكرين شوت…

## 2. الحل في جملة
**"قول للـ AI عاوز إيه وبكام، يجيبلك أحسن عرض من متجر موثوق، ودوسة واحدة تدفع وتطلب."**

```
المستخدم: "عاوز سماعة لاسلكية جديدة في حدود 500 Pi"
   │
   ▼
الـ AI يدور في: Map of Pi + متاجر Mainnet + شركاء Pi Dalil + الويب (بحذر)
   │
   ▼

   │
   ▼
كروت منتجات: صورة · السعر بـ Pi (≈ $) · ⭐ المنتج 4.6 (38) · 🛡️ ثقة المتجر 87 · أهم 2-3 تعليقات
   │
   ▼
[ادفع 480 Pi] ← بياناتك (الاسم/العنوان/التليفون) متعبّية من البروفايل
   │
   ▼

   │
   ▼

   │
```

| الطبقة | المصدر | إزاي نعرف إنه بيقبل Pi | الدفع من جوه Pi Dalil |
|---|---|---|---|
| 🟢 **1 — رسمي** | **Map of Pi** (الفائز بهاكاثون Commerce 2024، مفتوح المصدر PiOS) | مسجّل كبائع على الخريطة، وفيه منتجات بأسعار Pi وتقييمات و`trust_meter_rating` | ✅ |
| 🟢 **1 — رسمي** | **تطبيقات Pi Mainnet** فئة التجارة (`*.pinet.com`) | موجود في Pi Browser ومعتمد من Pi | ✅ |
| 🟢 **1 — شريك** | **Pi Dalil Merchant** (متاجر بتسجّل عندنا) | التاجر عمل Sign-in with Pi + ربط محفظته + وافق على الشروط | ✅ (طلب تلقائي كامل) |
| 🟡 **2 — ويب** | مواقع على الإنترنت بتقول إنها بتقبل Pi (بحث ويب + متصفح حقيقي) | لازم نلاقي دليل: صفحة دفع Pi حقيقية، محفظة معروفة، تاريخ على البلوكتشين | ⚠️ فقط لو رقم الثقة ≥ 60؛ غير كده بيظهر كـ"معلومة" بدون زرار دفع |
| 🔴 **مرفوض** | أي موقع بيطلب الـ **passphrase** / الكلمات الـ 24 | — | ❌ يتحجب فوراً ويتسجل كنصب |

**API بتاع Map of Pi** (من الكود المفتوح `map-of-pi/map-of-pi-frontend`):
- `POST /sellers/fetch` — بائعين في منطقة جغرافية + `search_query`
- `GET /sellers/item/{sellerId}` — منتجات البائع (اسم، وصف، سعر بـ Pi، المخزون)
- `GET /review-feedback/{userId}` — التقييمات (rating، comment، صورة، تاريخ)
- `GET /sellers/{sellerId}` — `average_rating`، `isRestricted`، `fulfillment_method`، `order_online_enabled_pref`
- `POST /orders` — إنشاء طلب (محتاج تنسيق/شراكة مع فريق Map of Pi علشان ننشئ طلب نيابة عن المستخدم)

## 4. معادلة الثقة — **Pi Trust Score (0–100)**

رقم صغير بيظهر على كل كارت (🛡️ 87). المعادلة **حتمية** (deterministic) في كود السيرفر، الـ AI مش بيحطها ولا يقدر يغيرها.

```
TrustScore = round( 100 × (0.25·O + 0.20·R + 0.20·W + 0.15·P + 0.10·D + 0.10·F) ) − Penalties
```

| الرمز | الإشارة | إزاي بتتحسب (0 → 1) | المصدر |
|---|---|---|---|
| **O** | الوجود الرسمي | Partner موثّق = 1 · Map of Pi بائع نشط = 0.9 · تطبيق Mainnet = 0.9 · ويب فقط = 0.2 | Map of Pi / Pi Browser / سجل الشركاء |
| **R** | التقييمات (Bayesian) | `R̄ = (C·m + Σr) / (C + n)` حيث `m = 3.5` و`C = 10` ← `R = (R̄ − 1) / 4` · مضروبة في `min(1, log10(n+1)/2)` علشان متجر عنده تقييم واحد 5 نجوم ميبقاش زي متجر عنده 100 | Map of Pi reviews + تقييمات Pi Dalil |
| **W** | تاريخ المحفظة على البلوكتشين | `0.5·min(1, عمر_المحفظة_بالأيام / 365) + 0.5·min(1, log10(عدد_المدفوعات_المستلمة+1) / 3)` | Pi Horizon API (`/accounts/{id}`، `/accounts/{id}/payments`) |
| **P** | منطقية السعر | 1 لو السعر بين 0.5× و 1.5× من متوسط نفس المنتج في المتاجر التانية · بيقل خطياً لحد 0 عند 0.2× أو 3× | مقارنة العروض + سعر Pi السوقي |
| **D** | الموقع/الدومين | HTTPS (0.3) + عمر الدومين ≥ سنة (0.4، عبر RDAP) + عنوان/تليفون/سياسة استرجاع (0.3) | فحص الموقع بالمتصفح |
| **F** | سجل التنفيذ | `طلبات اتسلّمت / كل الطلبات` عبر Escrow بتاعنا (يبدأ 0.5 للمتجر الجديد) · ناقص `2 × نسبة النزاعات` | قاعدة بيانات Pi Dalil |

**عقوبات (Penalties):**
| الحالة | العقوبة |
|---|---|
| بيطلب passphrase / بيحوّل لصفحة تسجيل دخول مزيفة | **الرقم = 0 + حجب** |
| `isRestricted = true` في Map of Pi | −40 |
| دومين عمره أقل من 30 يوم | −25 |
| بلاغات نصب مؤكدة من المستخدمين | −15 لكل بلاغ (حد أقصى −45) |
| سعر "مستحيل" (أقل من 0.2× السوق) | −20 + تحذير "عرض أحلى من الحقيقة" |

**الدرجات:**
| الرقم | الشكل | السلوك |
|---|---|---|
| 80–100 | 🟢 موثوق جداً | دفع عادي |
| 60–79 | 🟢 موثوق | دفع عادي |
| 40–59 | 🟡 بحذر | الدفع مسموح بس بتأكيد إضافي + الـ Escrow إجباري |
| < 40 | 🔴 غير موثوق | **مفيش زرار دفع** — بيظهر بس لو المستخدم طلب |

**تقييم المنتج** بيتحسب بنفس معادلة Bayesian لكن على تقييمات المنتج نفسه، وبيظهر كرقم صغير ⭐ 4.6 (38) جنب رقم ثقة المتجر. لو مفيش تقييمات للمنتج، بيظهر "منتج جديد — مفيش تقييمات" بدل ما نخترع رقم.

**ملخص التعليقات:** الـ AI بيلخص أهم 2-3 تعليقات (إيجابي/سلبي) من التقييمات الحقيقية بس، وكل جملة مربوطة بالتعليق الأصلي — ممنوع يألف تعليقات.

## 5. الدفع بـ Pi — إزاي "دوسة واحدة" تشتغل

**المشكلة التقنية:** Pi SDK في الواجهة (`Pi.createPayment`) بيدفع **لمحفظة التطبيق** مش لمحفظة المتجر مباشرة.

**الحل = Escrow (حجز) — نفس فكرة "Hold → Capture" في Dalil PayPal:**

```
1) U2A: Pi.createPayment({ amount, memo, metadata:{ offerSig, orderDraftId } })
      onReadyForServerApproval → السيرفر: يتحقق من التوقيع + حدود الصرف → POST /v2/payments/{id}/approve
      المستخدم يوقّع في Pi Wallet
      onReadyForServerCompletion → السيرفر: يتحقق من txid على البلوكتشين → POST /v2/payments/{id}/complete
   ⇒ الفلوس "محجوزة" في محفظة Pi Dalil — حالة: HELD

2) تسجيل الطلب في المتجر تلقائياً (القسم 6) — حالة: ORDER_PLACED

3) التحويل للمتجر (A2U / معاملة من محفظة التطبيق لمحفظة التاجر) — حالة: RELEASED
      • متجر شريك: بعد ما يأكد الطلب (أو يرفع رقم الشحن)
      • متجر 40–59: بعد ما المشتري يأكد الاستلام (أو بعد X يوم بدون نزاع)
   أو الإلغاء: لو المتجر رفض/مردّش خلال 48 ساعة ⇒ A2U يرجّع الفلوس للمشتري — حالة: REFUNDED
```

**ميزة ضخمة للرواد:** حماية المشتري. الفلوس مش بتروح لحد ما الطلب يتأكد، وده مش موجود في أي مكان في منظومة Pi النهارده.

**بدائل لازم نتأكد منها مع Pi:**
- `Pi.Wallet.submitTransaction(xdr)` — لو المحفظة بتوقّع XDR فيه دفع مباشر لعنوان التاجر، ممكن نعمل وضع "دفع مباشر" للمتاجر عالية الثقة (من غير Escrow).
- شروط Pi Developer Terms بخصوص الاحتفاظ بأموال المستخدمين (Escrow) — **لازم نتأكد قبل Mainnet**.

**قواعد أمان (من Dalil PayPal):**
- كل عرض **موقّع HMAC** من السيرفر بالسعر اللي اتشاف فعلاً — أي تعديل من المتصفح أو سعر مألّف من الـ AI ⇒ الدفع مرفوض.
- **حد صرف** (Mandate): أقصى مبلغ للعملية + "متاجر موثوقة فقط" — بيتفرض في كود السيرفر لحظة الـ approve.
- لا تسليم ولا تحويل للتاجر إلا لو `/complete` رجع 200 والـ txid اتأكد على البلوكتشين.
- Server API Key ومفتاح محفظة التطبيق على السيرفر بس.

## 6. تسجيل الطلب تلقائياً في المتجر

**بروفايل الشحن** (مرة واحدة): الاسم، التليفون، العنوان، المدينة، ملاحظات. محفوظ على الجهاز (IndexedDB) ومش بيتبعت إلا لحظة الشراء بموافقة صريحة ("هنبعت بياناتك للمتجر X").

| نوع المتجر | طريقة تسجيل الطلب |
|---|---|
| **شريك Pi Dalil** | **Merchant API**: `POST` webhook للتاجر فيه الطلب + بيانات الشحن + إثبات الدفع (HELD). التاجر يرد `accepted` + رقم الطلب. (ونوفّر لوحة تحكم بسيطة للتاجر اللي معندوش سيستم) |
| **Map of Pi** | `POST /orders` (بالتنسيق مع فريق Map of Pi) — أو كمرحلة أولى: رسالة طلب منسّقة للبائع + إشعار |
| **تطبيق Mainnet / موقع ويب** | **متصفح حقيقي** (Puppeteer من Dalil): الـ AI يملا فورم الطلب بالبيانات ويوقف **قبل** خطوة الدفع، يعرض للمستخدم screenshot "ده اللي هيتبعت" → المستخدم يأكد. (لو المتجر نفسه بيطلب الدفع جوه تطبيقه، بنفتحه للمستخدم بدل الـ Escrow) |
| **أي متجر تاني** | الـ AI يجهز رسالة طلب كاملة (واتساب/إيميل) + رقم المعاملة، والمستخدم يبعتها بدوسة |

**ضد الـ Prompt Injection:** محتوى صفحات المتاجر "بيانات مش أوامر"، والـ AI ممنوع يدخل passphrase أو أي بيانات غير بروفايل الشحن.

## 10. سيناريو العرض للحكام (2 دقيقة)
1. "عاوز سماعة لاسلكية جديدة في حدود 500 Pi" → 3 كروت من Map of Pi وشركاء، كل واحد عليه 🛡️ و ⭐ وتعليقات.
2. دوسة على 🛡️ → تفصيل المعادلة. ونجرب موقع نصب بيطلب passphrase → 🛡️ 0 ومحجوب.
3. "ادفع 480 Pi" → Pi Wallet (Testnet) → "محجوز" → الطلب ظهر في لوحة التاجر ببيانات الشحن تلقائياً.
4. التاجر يأكد → الفلوس اتحولت له → إيصال الثقة برقم المعاملة على البلوكتشين.

## 11. أسئلة لازم نتأكد منها
1. **Escrow:** هل شروط Pi بتسمح للتطبيق يحجز ويحوّل للتاجر؟ وإزاي التاجر بيستلم (A2U لـ uid ولا معاملة لعنوان محفظة)؟
2. **`Pi.Wallet.submitTransaction`:** هل بيسمح بدفع مباشر من محفظة المستخدم لعنوان التاجر؟
3. **Map of Pi:** صلاحية استخدام الـ API وإنشاء طلبات نيابة عن المستخدم (التواصل مع الفريق).
4. **مزود الـ AI:** نكمل بنفس مفتاح Meta من Dalil ولا مزود تاني؟
5. **شروط Pi Next** (هتتعلن 19 نوفمبر): Mainnet إجباري؟ App Studio؟ مسارات معينة؟
